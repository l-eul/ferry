# Ferry

Telegram-connected Ferry application. This distribution contains only the files needed to install and run the app; dependencies are installed locally with npm.

## Quick start (Windows)

1. Extract this folder.
2. Open `.env` after the first start prompt and enter your Telegram API credentials.
3. Double-click `START-FERRY.bat`.
4. Open http://localhost:8080.

Or use PowerShell as described below.

## 1. Install

Open PowerShell **in this folder** (the folder containing `package.json`) and run:

```powershell
npm install
```

## 2. Configure Telegram

Copy the example environment file:

```powershell
Copy-Item .env.example .env
```

Open `.env` and set your Telegram API credentials. Local app authentication is disabled by default; the Telegram account connection is the login used by Ferry:

```env
VITE_AUTH_ENABLED=false
```

Then set:

```env
TELEGRAM_API_ID=YOUR_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

Keep `TELEGRAM_API_HASH` private. Never commit `.env` or share a Telegram session string.

## 3. Start

```powershell
npm run dev
```

Open:

http://localhost:8080

## 4. First Telegram connection

Use the Telegram connection screen in the app. Enter your own phone number, the verification code Telegram sends you, and your 2FA password if Telegram requests it.

The app then works from the authenticated account's real Telegram dialogs instead of generated groups or members.

## Important

This app does not ship with `node_modules`; that directory is generated by `npm install` and can contain thousands of files. It is intentionally not included in this ZIP.

## Local data

The local development database is stored in `.ferry-data/` so your Telegram connection survives a normal server restart. Do not share that directory or your `.env` file.

## Session security

Ferry encrypts stored Telegram session strings at rest. For a production deployment, set a separate `FERRY_SESSION_KEY` and keep it private. If it is not set, Ferry derives the encryption key from `TELEGRAM_API_HASH`. Never share the database directory, `.env`, or session data.

## Product promise and limitations

Ferry is intentionally transparent about what it can and cannot do:

- It authenticates a real Telegram user account and works from that account's real dialogs.
- It does not generate, invent, or simulate groups or members.
- It can load only the members Telegram makes available to that authenticated account. Some private/supergroups require admin access, and hidden/restricted participant lists may not be enumerable.
- It can invite only users Telegram permits the account to invite. Recipient privacy settings, destination permissions, existing membership, bans, and Telegram rate limits can prevent an invite.
- Ferry stops an add run when Telegram returns a flood-wait instruction instead of repeatedly retrying the request.
- It does not bypass Telegram privacy, permission, or anti-spam restrictions.

These limitations should be part of the product description. Do not market Ferry as a way to bypass Telegram restrictions or as a guaranteed member-transfer service.

## Multi-user deployment

The included local configuration is intentionally convenient for a single local installation. For a public SaaS deployment, do not run with `VITE_AUTH_ENABLED=false`: each customer must have a distinct authenticated application identity so their encrypted Telegram session is isolated from every other customer. The deployment platform must provision Better Auth and a persistent database before launch.


### Private Telegram groups
Ferry can use private groups as sources when the connected Telegram account is already a member and Telegram makes that group's participants available to the account. Ferry resolves the group from the account's authenticated dialog list rather than reconstructing a private peer from a numeric ID. Telegram permissions and privacy restrictions remain enforced.

### Eligibility filtering
Ferry filters source members on the server before showing them for selection. By default it excludes bots, deleted accounts, members already in the destination, and previously recorded permanent invite failures. Optional activity filters can limit the eligible population to users active within 24 hours, 7 days, or 30 days when Telegram exposes enough activity information. The displayed eligible count is the population Ferry will offer for the operation.

Member enumeration is paged/streamed and is not intentionally capped at 10,000 users. Telegram remains authoritative over participant visibility, privacy, permissions, and rate limits.


## Public Telegram links

Ferry can resolve a public Telegram `@username` or `t.me/...` link for a source or destination when Telegram makes that entity available to the authenticated account. A public link does not bypass Telegram participant visibility, privacy, admin, invitation, or rate-limit rules. Private groups still require legitimate account access.
